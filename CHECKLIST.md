# Чеклист проверки перед отправкой задания

## ✅ Проверено

### 1. UI-код позволяет вызвать API для генерации отчётов
- ✅ Кнопка "Получить отчёт" вызывает функцию `fetchReport()`
- ✅ Функция `fetchReport()` отправляет GET запрос к `/reports` эндпоинту
- ✅ Токен Keycloak передаётся в заголовке `Authorization: Bearer <token>`
- ✅ Параметры фильтрации (date_from, date_to) передаются в URL
- ✅ Обработка ответа и отображение данных реализована

### 2. Реализация не позволяет генерировать отчёт пользователю, который не прошёл аутентификацию
- ✅ В UI: проверка `if (!keycloak?.token)` перед запросом
- ✅ В UI: отображение страницы входа, если пользователь не аутентифицирован
- ✅ В API: dependency `get_current_user_id` требует валидный токен
- ✅ В API: HTTP 401 возвращается, если токен отсутствует или невалиден
- ✅ В API: функция `get_current_user_id()` выбрасывает HTTPException 401 при отсутствии токена

### 3. Реализация позволяет генерировать авторизованному пользователю только собственный отчёт
- ✅ `user_id` извлекается из токена через `get_current_user_id` dependency
- ✅ `user_id` НЕ принимается из параметров запроса (только из токена)
- ✅ SQL-запросы содержат обязательное условие `WHERE user_id = {user_id}`
- ✅ Дополнительная валидация: проверка `user_id` в каждой строке результата
- ✅ Строки с несовпадающим `user_id` отбрасываются
- ✅ Логирование предупреждений о потенциальных утечках данных

### 4. Добавлена генерация отчётов по запросу пользователя из OLAP
- ✅ Запросы отправляются в ClickHouse (OLAP база данных)
- ✅ Используется таблица `reports_warehouse.prosthesis_usage_reports`
- ✅ Используется материализованное представление `daily_prosthesis_reports` для сводной статистики
- ✅ Данные получаются из предварительно агрегированной витрины (не вычисляются в реальном времени)
- ✅ Подключение к ClickHouse через `clickhouse-driver`

### 5. Предусмотрена генерация отчётов только за период, который уже обработан Airflow
- ✅ Проверка: `date_to` ограничивается до вчерашнего дня (данные за сегодня могут быть не готовы)
- ✅ Airflow обрабатывает данные ежедневно в 02:00 UTC
- ✅ Если запрошена дата позже вчерашнего дня, она автоматически ограничивается
- ✅ Логирование предупреждений о запросе недоступных данных
- ✅ Информационные сообщения в ответе API, если данных нет
- ✅ В UI: предупреждение о том, что данные за сегодня могут быть недоступны
- ✅ В UI: ограничение максимальной даты в input до вчерашнего дня

### 6. Обработка случая, когда данных ещё нет в OLAP
- ✅ Проверка наличия данных в результате запроса
- ✅ Если данных нет, возвращается пустой массив с информационным сообщением
- ✅ В summary добавляется поле `warning` или `info` с объяснением
- ✅ UI отображает предупреждения и информационные сообщения
- ✅ Пользователь получает понятное объяснение, почему данных нет

## Дополнительные проверки безопасности

- ✅ Все SQL-запросы используют параметризованные запросы (защита от SQL injection)
- ✅ Валидация данных на уровне приложения
- ✅ Логирование всех операций аутентификации и запросов
- ✅ Обработка ошибок с понятными сообщениями

## Архитектурные решения

- ✅ RBAC реализован на уровне API (фильтрация по user_id)
- ✅ Аутентификация через Keycloak с PKCE
- ✅ Данные из OLAP (ClickHouse) - быстрый доступ без вычислений в реальном времени
- ✅ ETL-процесс через Airflow для подготовки витрины

# Архитектурное решение: Сервис отчётов

## Обзор

Сервис отчётов предоставляет пользователям возможность получать данные о работе своих протезов в виде структурированных отчётов. Решение включает ETL-процесс для объединения данных из разных источников и формирование витрины отчётности в OLAP БД.

## Компоненты системы

### 1. Frontend Web (React)
**Назначение**: Интерфейс для просмотра и скачивания отчётов

**Функции**:
- Отображение списка доступных отчётов
- Просмотр отчётов в браузере
- Скачивание отчётов в форматах PDF/CSV
- Аутентификация через BFF Service

### 2. Reports API (SpringBoot)
**Назначение**: Backend-сервис для генерации и предоставления отчётов

**Функции**:
- Аутентификация запросов (через BFF Service)
- Проверка прав доступа (RBAC) — пользователь видит только свои отчёты
- Формирование запросов к витрине отчётности (ClickHouse)
- Генерация отчётов в форматах PDF и CSV
- Кэширование часто запрашиваемых отчётов

**API Endpoints**:
- `GET /reports` — получение списка доступных отчётов
- `GET /reports/{reportId}` — получение конкретного отчёта
- `GET /reports/{reportId}/download?format=pdf|csv` — скачивание отчёта

### 3. ClickHouse (OLAP Database)
**Назначение**: Витрина отчётности для быстрого доступа к агрегированным данным

**Структура данных**:
- **Таблица `prosthesis_usage_reports`**:
  - `user_id` — идентификатор пользователя
  - `prosthesis_id` — идентификатор протеза
  - `date` — дата записи
  - `sensor_data` — данные с датчиков (JSON)
  - `movements_count` — количество движений
  - `battery_level` — уровень заряда батареи
  - `usage_hours` — часы использования
  - `crm_user_name` — имя пользователя из CRM
  - `crm_prosthesis_model` — модель протеза из CRM
  - `crm_order_date` — дата заказа из CRM

**Преимущества ClickHouse**:
- Высокая производительность для аналитических запросов
- Колоночное хранение данных
- Эффективная агрегация больших объёмов данных
- Поддержка временных рядов

### 4. Apache Airflow (ETL Orchestrator)
**Назначение**: Оркестрация ETL-процесса для подготовки витрины отчётности

**ETL-процесс (DAG)**:

#### Extract (Извлечение данных)
1. **Из PostgreSQL**:
   - Телеметрия протезов (данные датчиков, движения, батарея)
   - Временные ряды использования протезов
   - Фильтрация по дате (инкрементальная загрузка)

2. **Из CRM DB (Oracle)**:
   - Информация о пользователях (имя, email, дата регистрации)
   - Данные о протезах (модель, серийный номер, дата изготовления)
   - История заказов и обслуживания

#### Transform (Трансформация данных)
- Объединение данных из двух источников по `user_id` и `prosthesis_id`
- Агрегация данных по дням/неделям/месяцам
- Расчёт метрик:
  - Среднее количество движений в день
  - Средний уровень заряда батареи
  - Общее время использования
  - Пиковые периоды активности
- Очистка и валидация данных
- Обработка пропущенных значений

#### Load (Загрузка в витрину)
- Загрузка обработанных данных в ClickHouse
- Обновление существующих записей (upsert)
- Удаление устаревших данных (retention policy)

**Расписание**: Ежедневно в 02:00 UTC (после завершения дневных операций)

**Мониторинг**:
- Уведомления при ошибках ETL
- Логирование всех этапов процесса
- Метрики производительности

### 5. PostgreSQL (OLTP Database)
**Назначение**: Основная база данных для хранения телеметрии протезов

**Данные**:
- Телеметрия в реальном времени от протезов
- Данные датчиков (миосигналы)
- События движений
- Статус батареи

### 6. CRM DB (Oracle Database)
**Назначение**: База данных CRM-системы (Битрикс24)

**Данные**:
- Профили пользователей
- Информация о протезах
- История заказов
- Данные о производстве и обслуживании

### 7. BFF Service (Backend for Frontend)
**Назначение**: Аутентификация и авторизация запросов

**Функции**:
- Проверка токенов аутентификации
- Валидация прав доступа пользователя
- Передача контекста пользователя в Reports API

## Поток данных

### ETL-процесс (ежедневно)

```
1. Airflow запускает DAG в 02:00 UTC
2. Extract:
   - Чтение данных из PostgreSQL (за последние 24 часа)
   - Чтение данных из CRM DB (обновления пользователей/протезов)
3. Transform:
   - Объединение данных по user_id и prosthesis_id
   - Агрегация и расчёт метрик
   - Валидация данных
4. Load:
   - Загрузка в ClickHouse (upsert)
   - Очистка старых данных (если необходимо)
5. Уведомление о завершении/ошибках
```

### Запрос отчёта пользователем

```
1. Пользователь открывает Frontend Web
2. Frontend отправляет запрос в Reports API с токеном
3. Reports API проверяет токен через BFF Service
4. BFF Service валидирует права доступа (RBAC)
5. Reports API формирует SQL-запрос к ClickHouse:
   - Фильтрация по user_id (только данные пользователя)
   - Агрегация по нужному периоду
6. ClickHouse возвращает данные
7. Reports API форматирует данные в PDF/CSV
8. Frontend отображает или скачивает отчёт
```

## Безопасность

### Контроль доступа (RBAC)
- Пользователь может запрашивать только отчёты по своим протезам
- Проверка `user_id` на всех уровнях:
  - BFF Service проверяет токен и извлекает `user_id`
  - Reports API добавляет фильтр `WHERE user_id = ?` ко всем запросам
  - ClickHouse не содержит данных других пользователей в результатах

### Аутентификация
- Все запросы проходят через BFF Service
- Использование JWT токенов
- Токены не передаются напрямую в ClickHouse

### Изоляция данных
- Данные в ClickHouse агрегированы и не содержат чувствительной информации
- Персональные данные хранятся только в CRM DB и PostgreSQL
- В витрине отчётности хранятся только необходимые для отчётов поля

## Производительность

### Оптимизация запросов
- Индексы в ClickHouse по `user_id`, `prosthesis_id`, `date`
- Партиционирование таблиц по дате
- Кэширование часто запрашиваемых отчётов в Reports API

### Масштабируемость
- ClickHouse горизонтально масштабируем
- Airflow может обрабатывать несколько DAG параллельно
- Reports API может масштабироваться горизонтально

## Мониторинг и логирование

- Логирование всех запросов к Reports API
- Мониторинг производительности ETL-процесса
- Алерты при ошибках загрузки данных
- Метрики использования API (количество запросов, время ответа)

## Форматы отчётов

### PDF
- Структурированный отчёт с графиками
- Временные ряды использования
- Сводные метрики
- Информация о протезе из CRM

### CSV
- Табличные данные для анализа
- Все метрики в структурированном виде
- Поддержка импорта в Excel/Google Sheets
